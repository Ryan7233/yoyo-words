# 成人词汇质量重建方案

## 目标

成人词卡需要同时满足四件事：

1. 主词性和中文义是现代常用义。
2. 英英解释与该词性、该中文义表达同一个意思。
3. 解释使用成人学习者能理解的常用英语。
4. 例句、搭配、词族和构词信息各司其职，不用通用背景内容冒充专属关联。

本方案不承诺用自动流程证明 6,912 条内容“绝对零错”。它把风险分层，
让可确定的格式和旧词典缺陷在 CI 中归零，让高频语义内容经人工确认，
并把长尾语义风险变成可追踪、可复核、不会静默退化的数据。

## 全库交付范围（2026-09-22 更新）

本次目标是全库更新与逐词复核，不再以高频抽查或正则扫描代替全量语义检查。
成人四条路线共享 6,912 个词，v29 基线包含 8,188 条词性记录（后续补义会增加）；此外纳入儿童 459 条、
Kiwi 24 条词语/口语块。路线之间不重复计数，所有现有学习 ID 保留。

按每批最多 100 个完整词条编排，不拆散同词的不同词性。每条先更新，再由不同
复核者核对常用义、词性、中英一致性、例句、搭配、关联词及读音；儿童内容另查
年龄适宜性。词根或搭配不适用时可以不添加，不为覆盖率编造内容。

`node scripts/audit_vocab_coverage.mjs --write` 输出全量任务清单及字段覆盖。
`--require-complete` 只有所有词条都有匹配当前内容哈希的独立复核记录时才成功。
记录放在 `scripts/data/vocab-verification.json`，以 `adult/adult:word`、
`children/id` 或 `kiwi/id` 为键，包含 `author`、`reviewer`、`verdict`、
`content_sha256`、`checks` 和带 URL/核对说明的 `evidence`。
此门槛只核验记录完整和未过期，不自动证明复核者判断正确，更不代表零错误。
已增加单列的 `model_semantic_reviewed` 计数：不同子任务逐词语义复核且释义、例句、
搭配与当前产物逐字段一致时才计入。它不是专业人工审校，也不能冒充逐词外部

## 目标数据结构

人工审定内容按义项保存，而不是给整个单词共用一句解释：

```json
{
  "en": "relative",
  "senses": [
    {
      "pos": "adj.",
      "zh": "相对的、相关的",
      "definition": "considered by comparing it with something else",
      "example": "The task is easy relative to the last one.",
      "collocations": ["relative importance", "relative size"],
      "definitionStatus": "reviewed"
    },
    {
      "pos": "n.",
      "zh": "亲戚、亲属",
      "definition": "a person who belongs to the same family",
      "example": "Most of her relatives live nearby.",
      "collocations": ["close relative", "distant relative"],
      "definitionStatus": "reviewed"
    }
  ]
}
```

`definitionStatus` 只能是：

- `generated`：机器生成并通过自动检查，仍需语义复核。
- `reviewed`：人工确认了词性、中文义、英英解释和例句的一致性。

快照测试只能防止已审定内容退化，不能把未经审定的数据自动变成正确答案。

## 数据来源与生成原则

### 规格不能只依赖一个字段

当前 `zh + pos` 比原始英文释义更适合作为起点，但也存在中文混合多个词性、
主词性不常用等问题。因此生成前必须综合：

- 人工审定的中文义和词性；
- 现代语料中的词性和使用频率；
- 至少一个可追溯的词典或词汇关系来源；
- 当前学习路线和曝光频率。

### 受控释义词表

建立约 2,500–3,000 个基础 lemma 的项目自有释义词表。功能词、必要的解释
元词汇和常用屈折变化应列入允许范围。专业术语、专名和不可替代词允许例外，
但必须在报告中标记，不能为了通过规则写出不自然的解释。

### 生成与校验分离

生成器输出结构化义项，校验器独立检查：

- 词性和中文义语义是否一致；
- 回译结果是否仍指向同一义项；
- 是否循环使用目标词；
- 是否为残句、交叉引用或古旧缩写；
- 释义难度、长度和完整性；
- 例句是否真正使用目标词的当前词性和义项；
- 搭配是否自然且属于该义项。

回译或模型判定只是风险检测器，不能由同一个生成过程自我签字。高风险冲突
必须进入人工队列。

## 分阶段实施

### P0：止血与可观察性

- 对前 500 高频词生成逐条诊断表。
- 修复已确认的缩写、专名、字母义、错误词性、古旧交叉引用和明显残句。
- 将人工内容移入可审阅 CSV，不继续散落在构建代码里。
- CI 固定拦截高置信缺陷；难度指标只报告，不直接删除或改义。

完成标准：

- 已确认的高频错义为 0。
- 所有人工审定行能够稳定重建，生成产物可重复。
- 审计报告明确区分 `defect / risk / heuristic`。

### P1：前 500 逐义项重建

- 人工确认每个词的主词性、中文义和需要保留的常用第二词性。
- 每个义项补英英解释和自然例句。
- 内容词补 1–3 个高频搭配。
- 词族、构词拆解和同构词例词分开展示。

完成标准：

- 前 500 的词性、中文义、英英解释和例句 100% 人工确认。
- 0 个循环定义、残句、旧式交叉引用和明确义项错配。
- 多词性词按义项分别展示定义和例句。

### P2：扩展到全部 6,912 词

- 按频率分批生成，不一次性覆盖全部词库。
- 每批经过结构校验、受控词汇检查、独立语义校验和抽样人工复核。
- 考研长词、抽象词、多词性词和同形异义词进入高风险抽样层。
- 只有人工确认过的内容才能从 `generated` 升级为 `reviewed`。

建议批次：`501–1,800`、`1,801–3,500`、`3,501–6,912`。

### P3：持续质量闸门

- 构建产物记录源文件哈希、生成提示版本、模型版本和审定状态。
- CI 比较审计摘要，禁止已归零的高置信缺陷重新出现。
- 已审定内容改变时要求显式更新 golden 数据，而不是自动接受新结果。
- 每次发布优先抽查变更词和移动端首屏词。

## 发布门槛

每一批发布前至少满足：

- 构建和测试全绿。
- 全量审计完成，报告与当前 `adult-words.js` 哈希一致。
- 高频错义、空释义、旧式交叉引用和明显残句均未新增。
- 所有 `reviewed` 行的生成结果与审定 CSV 一致。
- 在窄屏 iPhone 尺寸上验证多词性、长单词、例句和搭配不会破坏导航。
